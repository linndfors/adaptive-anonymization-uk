# Adaptive Anonymization of Ukrainian Resumes

Adaptive anonymization of resume text using a trained action regressor
(`HistGradientBoostingRegressor`). The model selects fragments to mask or
generalize while limiting information loss. Inference runs locally on one
resume; a reference corpus is used for training and evaluation.

Requires **Python 3.12** and **uv**. Run commands from the repository root.
Train the model before starting the demo.

## 1. Install

```bash
uv sync --locked --extra data --extra detection --extra ui
```

## 2. Prepare data

Download WorkUA resumes:

```bash
uv run python scripts/fetch_workua.py --out data/raw/all_resumes.csv
```

Two prepared resources are also required:

- `data/processed/e3_jsi_uk.jsonl` — Ukrainian texts with annotated entity spans.
- `data/taxonomy/category_map.json` — term-to-category lookup for generalization.

These files are not included or automatically generated by the training command.
See [data formats and preparation](data/README.md).

Prepare shared detector and training resources:

```bash
uv run python scripts/prepare_resume_resources.py \
  --config configs/baselines/adaptive_resume_v3_3.json
```

This configuration prepares shared resources; the model is trained below.

## 3. Train

Reserve person-disjoint splits, train the regressor and add one round of
training on states visited by the controller:

```bash
uv run python scripts/action_data.py \
  --train-persons 300 --validation-persons 80 --test-persons 60 \
  --reference-size 6000 --reuse-historical-background \
  --out artifacts/training/data

uv run python scripts/train_action_resume.py \
  --data-dir artifacts/training/data \
  --out artifacts/training/offline

uv run python scripts/train_action_onpolicy.py \
  --model artifacts/training/offline/model.pkl \
  --data-dir artifacts/training/data \
  --out artifacts/training/onpolicy
```

Keep the saved splits unchanged. Requested counts require enough eligible
linked people in the input dataset.

## 4. Select model settings

Download the semantic encoder, then select the model and settings on validation
data. The selected model is saved at the path used by the demo.

```bash
uv run hf download sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2 \
  --revision e8f8c211226b894fcb81acc59f3b34ba3efd5f42 \
  --local-dir artifacts/models/semantic_minilm \
  --include '*.json' model.safetensors tokenizer.model sentencepiece.bpe.model unigram.json

uv run python scripts/select_action_operating_point.py \
  --model artifacts/training/offline/model.pkl \
  --candidate-model artifacts/training/onpolicy/model.pkl \
  --documents artifacts/training/offline/validation_documents.pkl \
  --data-dir artifacts/training/data \
  --out artifacts/models/resume_action_v5
```

In `configs/adaptive_resume.json`, set `adaptive.utility_floor` to the value
of `selected_settings.utility_floor` in the generated model's `report.json`.

## 5. Run

Streamlit demo:

```bash
uv run streamlit run app/text_demo.py
```

Paste a resume, upload a UTF-8 `.txt` file or choose an example. The interface
offers the adaptive model and four fixed policies, highlighted edits, text
export and an optional comparison of all methods.

Fixed policies are labelled L1, L2 and L3 by strategy; they use the current text
parser and transformations rather than the historical structured-field renderer.

Enable **Підключити корпус** to use the standard local corpus automatically.
The app reads `data/corpus/default.jsonl`; if it is absent, it uses the six
authored examples and labels the corpus **Демо**. No download is required.
Choose **Власний** in the corpus panel to upload CSV, JSON/JSONL or TXT files.
CSV/JSON records need a `text` field; structured WorkUA records are also supported.
The corpus evaluates outputs without changing the selected policy. For an
ordinary input, the original is added once as a search target (S1). BM25 and character
TF-IDF try to recover it from the anonymized query. The main metric is the
largest expected reciprocal rank (RR) before and after, with its relative
percentage change. A value of 1 means an attacker still ranks the target first.
Ties are handled exactly. The input remains in
session memory and is not saved to the corpus file.
Search uses content with common field headings, service masks and formatting
removed consistently from the pool and queries. Target TF-IDF similarity and
the score gap to the nearest competitor explain changes while rank stays first.
Lower similarity is a weaker textual match, not proof of lower linkage success
when RR remains 1. Scores are read directly from the fixed index.

If another resume of the same person is known, select it for a separate
cross-resume attack (S2). That scenario excludes exact input copies and does
not insert the input. RR is a retrieval score, not a calibrated probability of
identification. UI S1 results do not replace the independent corpus S2 results.

For a guided demonstration, choose **Підтримка**, **Аналітика**, **Логістика**,
**Облік**, **Персонал** or **Проєкти**, then click **Анонімізувати**. Each curated synthetic pair
automatically selects the standard background and adds one fictional related
resume in session memory. The selected target explicitly identifies S2.
The six inputs use paragraphs and ordinary work-history descriptions, with different
names, lengths and writing styles. Both members of each pair are synthetic.
Choose **Оригінал резюме (автоматично)** to compare S1 on the same input; the
synthetic related target is then removed from the scoring pool. These are
illustrations selected for the prepared 6000-record background, not independent
test cases. Scores are recomputed; changing the background can change them.
A fresh session opens the support S2 example with its paired target and corpus enabled.
Scenario definitions and synthetic-example provenance are available under **Довідка**;
they are kept out of the main editing view.

Command-line processing of an existing text file:

```bash
mkdir -p artifacts/outputs
uv run python scripts/anonymize_resume.py \
  --input resume.txt --output artifacts/outputs/resume_anonymized.txt
```

## 6. Evaluate

Evaluate the selected model on the reserved test people:

```bash
uv run python scripts/evaluate_action_resume.py \
  --model artifacts/models/resume_action_v5/model.pkl \
  --data-dir artifacts/training/data \
  --split test --without-previous-risk \
  --out artifacts/evaluations/test
```

Output directories must be new. Generated data, weights and metrics remain
under Git-ignored paths. Retraining produces a new experiment; it does not
guarantee the original weights or scores.

The active configuration is `configs/adaptive_resume.json`. Read
[the method description](docs/action-model-v5.md) for the learning target and
[the command map](scripts/README.md) for additional evaluation tools.
