# Адаптивна анонімізація українських резюме

Система приховує персональні дані та узагальнює відомості в резюме. Навчена
модель оцінює можливі зміни, а алгоритм обирає їх з урахуванням втрати інформації.
Результат можна переглянути у вебінтерфейсі Streamlit або зберегти в текстовий файл.

Для роботи потрібні **Python 3.12** та **uv**. Усі команди нижче виконуйте з кореня
репозиторію — папки `adaptive-anonymization-uk`.

## З чого почати

- **Модель і ресурси вже підготовлені локально:** встановіть залежності та запустіть
  демо за розділами 1 і 5.
- **Ви щойно завантажили репозиторій:** послідовно виконайте розділи 1–5.
  Дані й ваги моделі не входять до Git; модель потрібно навчити.

## 1. Встановлення

```bash
uv sync --locked --extra data --extra detection --extra ui
```

Звичайний запуск використовує локальні моделі та правила. Ключ OpenAI для нього
не потрібен.

## 2. Підготовка даних

Завантажте корпус резюме WorkUA:

```bash
uv run python scripts/fetch_workua.py --out data/raw/all_resumes.csv
```

Додатково підготуйте два файли:

| Файл | Призначення |
|---|---|
| `data/processed/e3_jsi_uk.jsonl` | Україномовні тексти E3-JSI з розміткою сутностей для перевірки детектора |
| `data/taxonomy/category_map.json` | Словник категорій для узагальнення професійних термінів |

Ці файли **не завантажуються й не створюються командою навчання**. Їхні формати
та спосіб підготовки словника описано в [документації даних](data/README.md).

Підготуйте детектор сутностей і спільні ресурси навчання:

```bash
uv run python scripts/prepare_resume_resources.py \
  --config configs/baselines/adaptive_resume_v3_3.json
```

Назва конфігурації тут історична: команда лише готує спільні ресурси, а не навчає
попередню адаптивну модель.

## 3. Навчання моделі

Спочатку сформуйте навчальну, валідаційну та тестову вибірки. Резюме однієї людини
не повинні потрапляти до різних вибірок.

```bash
uv run python scripts/action_data.py \
  --train-persons 300 --validation-persons 80 --test-persons 60 \
  --reference-size 6000 --reuse-historical-background \
  --out artifacts/training/data
```

Далі навчіть регресор, який прогнозує ефект можливих змін:

```bash
uv run python scripts/train_action_resume.py \
  --data-dir artifacts/training/data \
  --out artifacts/training/offline
```

Доповніть навчання прикладами зі станів, які виникають під час роботи алгоритму:

```bash
uv run python scripts/train_action_onpolicy.py \
  --model artifacts/training/offline/model.pkl \
  --data-dir artifacts/training/data \
  --out artifacts/training/onpolicy
```

Для вказаних розмірів вибірок у корпусі має бути достатньо людей із кількома
пов’язаними резюме. Збережений поділ вибірок надалі не змінюйте.

## 4. Вибір моделі та параметрів

Завантажте модель семантичної схожості, потрібну для оцінювання збереження змісту:

```bash
uv run hf download sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2 \
  --revision e8f8c211226b894fcb81acc59f3b34ba3efd5f42 \
  --local-dir artifacts/models/semantic_minilm \
  --include '*.json' model.safetensors tokenizer.model sentencepiece.bpe.model unigram.json
```

Оберіть модель і параметри на валідаційній вибірці:

```bash
uv run python scripts/select_action_operating_point.py \
  --model artifacts/training/offline/model.pkl \
  --candidate-model artifacts/training/onpolicy/model.pkl \
  --documents artifacts/training/offline/validation_documents.pkl \
  --data-dir artifacts/training/data \
  --out artifacts/models/resume_action_v5
```

Вибрану модель буде збережено в `artifacts/models/resume_action_v5/model.pkl` —
саме цей шлях використовує демо. З отриманого `report.json` перенесіть значення
`selected_settings.utility_floor` у параметр `adaptive.utility_floor` файлу
`configs/adaptive_resume.json`.

## 5. Запуск і використання

### Вебінтерфейс

```bash
uv run streamlit run app/text_demo.py
```

1. Вставте резюме, завантажте файл `.txt` у кодуванні UTF-8 або виберіть приклад.
2. Виберіть адаптивну модель чи фіксовану політику.
3. Натисніть **Анонімізувати**.
4. Перегляньте виділені зміни та завантажте результат. За потреби відкрийте порівняння методів.

Доступні адаптивна модель, приховування лише прямих даних (L1), узагальнення (L2),
сильне узагальнення (L3) та маскування деталей. Позначення L1–L3 описують стратегію;
ці політики в інтерфейсі використовують спільні поточні засоби обробки тексту.

### Необов’язкове підключення корпусу

Перемикач **Підключити корпус** додає перевірку пошукового зв’язування.
Він не змінює рішення адаптивної моделі: вона може анонімізувати резюме без корпусу.

- Стандартний корпус читається з `data/corpus/default.jsonl`. Якщо файла немає,
  використовуються шість демонстраційних текстів із позначкою **Демо**.
- Власний корпус можна завантажити у форматі CSV, JSON, JSONL або TXT.
  Для CSV/JSON достатньо поля `text`; поле `person_id` дозволяє позначити резюме однієї людини.
- Для звичайного введеного тексту оригінал додається до пошукового пулу один раз.
  Перевірка показує, чи можна знайти його за анонімізованим текстом (сценарій S1).
- Підготовлені приклади використовують інший сценарій (S2): пошук другого,
  заздалегідь написаного синтетичного резюме тієї самої вигаданої людини.
  Для перевірки пошуку оригіналу виберіть **Оригінал резюме (автоматично)**.

Показник **RR** характеризує місце цільового резюме в результатах пошуку BM25
та символьного TF-IDF. Значення `1` означає перше місце без нічиєї; нижче значення
означає гіршу позицію цілі. Це **не ймовірність деанонімізації**. Лексична схожість
також не є відсотком збережених фактів.

Демонстраційні пари підібрані для наочного показу на підготовленому фоновому корпусі.
Вони не є незалежною тестовою вибіркою; на іншому корпусі результати можуть відрізнятися.
Завантажені тексти обробляються в пам’яті поточної сесії й не записуються у файл корпусу.

### Обробка файла через термінал

```bash
mkdir -p artifacts/outputs
uv run python scripts/anonymize_resume.py \
  --input resume.txt --output artifacts/outputs/resume_anonymized.txt
```

## 6. Перевірка якості

Після вибору моделі виконайте оцінювання на відкладеній тестовій вибірці:

```bash
uv run python scripts/evaluate_action_resume.py \
  --model artifacts/models/resume_action_v5/model.pkl \
  --data-dir artifacts/training/data \
  --split test --without-previous-risk \
  --out artifacts/evaluations/test
```

Використовуйте нові каталоги результатів для кожного експерименту. Тестову вибірку
не використовуйте для підбору параметрів. Повторне навчання створює нову модель
і може дати інші результати.

## Структура проєкту

| Шлях | Призначення |
|---|---|
| `app/` | Інтерфейс Streamlit і демонстраційні приклади |
| `src/anonrisk_uk/` | Виявлення сутностей, перетворення тексту, адаптивний алгоритм і метрики |
| `scripts/` | Команди підготовки даних, навчання та оцінювання |
| `configs/adaptive_resume.json` | Основна конфігурація адаптивної моделі |
| `configs/baselines/` | Конфігурації попередніх підходів для підготовки ресурсів і порівняння |
| `docs/` | Технічний опис методу та відтворення експериментів |
| `data/`, `artifacts/` | Локальні дані, ваги та результати; до Git не додаються, крім `data/README.md` |
